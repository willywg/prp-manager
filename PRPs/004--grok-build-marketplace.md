## Goal
Add one entry for `prp-manager` to xAI's Grok Build plugin catalog ([xai-org/plugin-marketplace](https://github.com/xai-org/plugin-marketplace)) through a pull request. The entry points at `prp-manager/` in this repo, pinned to the commit approved in the Claude plugin directory (`379c267`). Nothing inside `prp-manager/` changes.

## Why
- Grok Build users can find and install the skill from `/marketplace` instead of copying folders
- The catalog accepts Claude-ecosystem plugins (`.claude-plugin/plugin.json`), so the existing plugin works as is
- The catalog's daily workflow advances the pin when `version` in `plugin.json` changes, so later releases need no manual PR

## What
After the PR merges, Grok Build lists `prp-manager` in the xAI Official marketplace, and installing it gives the `prp-manager` skill at version 1.3.0.

### Success Criteria
- [x] `grok plugin validate ./prp-manager` passes (1 skill dir, version 1.3.0)
- [x] `grok plugin install willywg/prp-manager@<sha>#prp-manager` installs `prp-manager v1.3.0 (subdir: prp-manager)`
- [x] Catalog entry added; `validate-catalog.py` and `generate-plugin-index.py --check` pass in the fork
- [x] The generated index lists the `prp-manager` skill for this entry
- [x] PR opened with the template filled in: https://github.com/xai-org/plugin-marketplace/pull/1635
- [x] README lists Grok Build as compatible (decided not to wait for the merge, see Notes)

### Known Gotchas
```yaml
# CRITICAL: Pin 379c267 (the commit approved in the Claude directory), not HEAD.
#   prp-manager/ is identical at HEAD, but the pin should match a reviewed release.
# CRITICAL: The source needs "path": "prp-manager". Without it the plugin root is
#   the repo root, which has no plugin.json and would ship README, PRPs and evals.
# INDEX: plugin_catalog.py reads manifests in order .grok-plugin/, .cursor-plugin/,
#   .claude-plugin/. scan_skills() resolves each "skills" entry and keeps it if it
#   contains SKILL.md, so "skills": ["./"] finds the root SKILL.md.
# UPDATES: bump-plugin-shas.yml runs daily and opens a bump PR when upstream HEAD
#   moved AND the manifest version changed. Same version means no bump. Keep
#   bumping plugin.json "version" with SKILL.md metadata.version (CLAUDE.md rule).
# KEYWORDS: must be brand-scoped; they trigger Grok's plugin suggestions. Generic
#   terms (planning, spec, prp) get sent back in review.
# NO DOMAINS: the plugin owns no product domain, so omit "domains".
# REVIEW: the source is a personal account. That matches the brand (the author's
#   own project), but say so in the PR notes.
# ENV: local python3 is broken; run the catalog scripts with
#   `uv run --no-project --python 3.12 python -I scripts/<script>.py`.
# AUTH: grok is not signed in on this machine, so an interactive session test
#   (skill visible in a Grok session) is not possible here.
```

## Validation Loop

### Level 1: Catalog checks (what CI runs)
```bash
uv run --no-project --python 3.12 python -I scripts/validate-catalog.py
uv run --no-project --python 3.12 python -I scripts/generate-plugin-index.py --check
# Expected: "Catalog OK" and a clean index check
```

### Level 2: Index content
```bash
jq '.plugins["prp-manager"] // (.plugins[]? | select(.name=="prp-manager"))' .grok-plugin/plugin-index.json
# Expected: sha 379c267..., version 1.3.0, components.skills = [prp-manager]
```

### Level 3: Install from the catalog (after merge)
```bash
grok plugin marketplace update
# In Grok Build: /marketplace -> prp-manager -> install; the skill is listed
```
